# 隐私与数据边界

这份文档比 README 里那段警告更重要。项目本身是「私人记忆库」，但它被开源成了**公开仓库**——这两件事天然冲突，所以请把下面读完。

## 三类绝不能提交的内容

| 类别 | 例子 | 为什么 |
| --- | --- | --- |
| **真实回忆正文** | 写进 `data/memories.js` 的个人经历、人名、地点、日期 | 一旦 push 到公开仓库，等于向全世界公开；Git 历史很难彻底抹掉 |
| **私人照片** | `assets/mem-10-*.jpg` 一类的自拍、家人合影、带定位信息的原图 | 人脸、居家环境、EXIF/GPS 都是不可逆的暴露 |
| **受版权保护的音频** | 商业发行的歌曲、专辑录音 | 开源许可证不覆盖第三方录音，分发会构成侵权 |

仓库里自带的 9 条记忆文案和 9 张 SVG 占位图都是**本项目原创的虚构内容**，不对应任何真实人物或事件，可以安全公开。

## 推荐的本地工作方式

### 1. 让 Git 忽略你对记忆数据的改动

`data/memories.js` 是被跟踪的示例文件。在本地把它换成真实内容后，执行：

```bash
git update-index --skip-worktree data/memories.js
```

之后再 `git status` 就不会看到它，`git add .` 也不会误带进去。想恢复跟踪：

```bash
git update-index --no-skip-worktree data/memories.js
```

### 2. 照片和音频交给 .gitignore

仓库的 `.gitignore` 已排除 `assets/*.jpg|png|webp`、`assets/music/*` 音频、`photos/` 等。注意 `git add -f` 会强行绕过忽略规则，别用。

### 3. 最稳的做法：私有仓库 + 公开模板

如果你打算长期记录真实回忆：

- 保留这个公开仓库作为「代码 / 模板」，只放示例数据；
- 另建一个**私有仓库**（或本地不同步的目录）存放你的 `data/memories.js` 和照片；
- 两边只同步代码，不同步数据。

## 门锁到底挡得住什么

`js/lock.js` 的隐私门锁：

- 开锁短语只以 **PBKDF2 / 迭代 SHA-256 摘要**形式存在浏览器本地，不存明文、不上传；
- 关标签页重新上锁、闲置自动上锁、切走标签页 30 秒上锁、快捷键立刻锁屏；
- 锁定期间主程序根本不渲染。

**但它不是加密。** 记忆正文仍是 `data/memories.js` 里的明文，懂技术的人打开开发者工具或直接看源码就能读到。它挡的是「随手打开你电脑/手机的人」，不是「一定要看你隐私的人」。

要把项目部署到公网并存放真实内容，别只靠门锁。数据层已经提供了内容加密的出口：

```js
// 导出：整包 JSON 用 AES-GCM 加密，密钥由短语经 PBKDF2-SHA256 派生
const buf = await SeaRepo.exportSealed('你的短语');
// importSealed(buf, '你的短语') 才能解回来
```

`.sea` 包在没有短语的情况下只是密文，可以直接放在公开位置或同步盘里。
注意两个前提：**短语丢了就真的打不开**（没有找回机制）；WebCrypto 需要 `https` 或 `localhost`，
直接双击 `file://` 打开时这个功能不可用。

## 如果已经误提交过

请按最坏情况处理——**把内容视为已泄露**：

1. 立刻停止向远端推送；
2. 修改 / 删除所有涉及的凭据、短语；如涉及照片与个人信息，评估是否需要进一步处理；
3. 清理 Git 历史（不是删文件就够了）：用 `git filter-repo` 或 BFG 从**所有**历史提交中移除，然后 force push；
4. 注意：fork、克隆、GitHub 缓存、搜索引擎快照都不受你控制，历史清理不能保证完全撤回；
5. 必要时在仓库设置里临时设为 private，或直接删除重建仓库。

## 一句话

**代码可以公开，记忆不要。** 这个仓库里的一切示例内容都是虚构的；你自己的那份，请留在本地或私有仓库。
